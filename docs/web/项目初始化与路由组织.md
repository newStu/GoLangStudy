# 项目初始化与路由组织

> 本篇对应仓库根目录的 `main.go`、`go.mod` 与 `router/` 包，记录 Web 项目从零初始化的过程，以及路由和全局常量的组织方式。

## 一、项目初始化

### 1.1 初始化 module

```bash
go mod init GoLangStudy
```

- `GoLangStudy` 是 **module 名**，它决定了本仓库内包的 import 路径：`main.go` 里引入自己的路由包写的是 `import "GoLangStudy/router"`。
- 如果项目以后要发布到 GitHub 供别人 `go get`，module 名建议直接用仓库地址（如 `github.com/gc_wangzhaoyu_ex/GoLangStudy`）。学习阶段用简短的名字完全没问题。

初始化后会在根目录生成 `go.mod`，它记录 module 名、Go 版本和所有依赖。

### 1.2 安装依赖包

```bash
# Web 框架
go get github.com/gin-gonic/gin

# ORM 和 MySQL 驱动（后面连数据库时用）
go get gorm.io/gorm
go get gorm.io/driver/mysql
```

几个要点：

- `go get` 会自动把包（及其依赖的依赖）写入 `go.mod`，并把精确版本写入 `go.sum`。**`go.mod` 和 `go.sum` 都要提交到 git**，别人拉下代码后执行 `go mod tidy` 或直接 `go run` 就能还原出完全一致的依赖环境。
- 本项目安装后在 `main.go` 里实际用到的只有 gin；gorm 相关包虽然进了 `go.mod` 但还没写使用它的代码——提前引入没问题，但注意 **`go.mod` 里有 ≠ 代码里在用**。执行 `go mod tidy` 可以清掉真正没用到的依赖。
- 被 gin 间接依赖的包（如 `bytedance/sonic`、`quic-go/quic-go`）在 `go.mod` 里标了 `// indirect`，表示"我没直接 import 它，是别人拉进来的"，理解即可，不用手动管理。

### 1.3 程序入口：main.go

```go
package main

import (
	"GoLangStudy/router"
)

const (
	DefaultPort = ":8080"
)

func main() {
	r := router.InitRouter()
	err := r.Run(DefaultPort)
	if err != nil {
		panic(err)
	}
}
```

入口只做三件事：初始化路由 → 启动 HTTP 服务 → 处理启动错误。

**`Run()` 的返回值必须处理**。端口被占用、权限不足等情况会通过 error 返回，如果像 `routersInit.Run(":8080")` 这样直接丢弃返回值，程序失败时会静默退出，很难排查。启动失败属于"无法继续的致命错误"，用 `panic(err)` 尽早暴露是常见做法。

## 二、路由的组织

### 2.1 目录结构

```
GoLangStudy/
├── main.go               // 入口：组装 + 启动
├── router/
│   ├── router.go         // 路由入口：创建引擎、建基础分组、调用各分类注册函数
│   ├── auth.go           // 认证类路由：注册、登录
│   └── business.go       // 业务类路由：订单等
```

核心思想：**一个分类一个文件，入口文件只负责组装**。以后新增"管理后台路由"，建一个 `admin.go` 写一个注册函数，再在 `router.go` 里加一行调用即可，不改动任何旧文件。

### 2.2 路由入口：router.go

```go
package router

import "github.com/gin-gonic/gin"

func InitRouter() *gin.Engine {
	r := gin.Default()

	// 基础分组：所有业务路由统一挂在这个前缀下
	base := r.Group("/api/" + APIVersion)

	registerAuthRoutes(base)
	registerBusinessRoutes(base)

	return r
}
```

- `gin.Default()` 创建的引擎自带 Logger（打印每个请求的日志）和 Recovery（panic 自动恢复，防止一个请求挂掉整个服务）两个中间件，学习阶段直接用它。
- `r.Group("/api/" + APIVersion)` 建立**统一前缀**，前缀里带版本号 `/api/v1` 是 Web API 的通用惯例——将来接口大改时新建 `/api/v2` 分组，旧版路由原样保留。

### 2.3 分类注册函数：auth.go

```go
package router

import (
	"net/http"

	"github.com/gin-gonic/gin"
)

// registerAuthRoutes 注册认证相关路由：注册、登录等
func registerAuthRoutes(r *gin.RouterGroup) {
	auth := r.Group("/auth") // 前缀自动拼接成 /api/v1/auth

	auth.POST("/register", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"message": "注册"})
	})
	auth.POST("/login", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"message": "登录"})
	})
}
```

三个值得注意的点：

1. **函数名小写开头**（`registerAuthRoutes`）：Go 用首字母大小写控制可见性——小写=包内私有，大写=导出可供其他包使用。这个函数只给同包的 `router.go` 调用，所以必须小写；同目录的文件属于同一个包，`router.go` 直接就能调用它，无需任何"引入"。
2. **参数类型是 `*gin.RouterGroup`** 而不是 `*gin.Engine`：分组只能由 `r.Group()` 产生，分类函数声明成接收分组，入口传什么前缀它就挂什么前缀，前后缀解耦。
3. **分组可以嵌套，前缀自动拼接**：`/api/v1` + `/auth` + `/register` 由 gin 层层拼好。每个文件只声明自己那一段，改版本号时只动 `router.go` 一处。

### 2.4 最终路由表

| 方法 | 路径 | 分类 |
|---|---|---|
| POST | `/api/v1/auth/register` | 认证 |
| POST | `/api/v1/auth/login` | 认证 |
| GET/POST | `/api/v1/orders` | 业务 |

## 三、全局常量的声明位置

### 3.1 判断标准：谁在用它

| 常量 | 谁用 | 放哪 |
|---|---|---|
| 端口 `":8080"` | 只有 `main.go` | `main.go` 顶部 `const` 块 |
| `APIVersion` 等路由常量 | 只有 `router` 包 | `router/const.go` |
| JWT 有效期、全局错误码 | 多个包共用 | 根目录 `consts/` 包 |

层次是**按使用者范围**选的，不是"项目变大就往上挪"：

- **就近放置是默认选择**——常量和它唯一的使用者待在一起，改、删都只看一处。
- **`consts/` 全局包是妥协**——只有当一个常量被多个包共用、放谁那里都别扭时才抽过去。无脑往全局包里塞，它会迅速变成没人敢清理的"杂物间"。

### 3.2 包内常量文件：router/const.go

```go
package router

const (
	// APIVersion API 版本号，升级 v2 时只改这一处
	APIVersion = "v1"
)
```

注意：**包名不变，还是 `router`**。Go 规定同一目录下所有 `.go` 文件必须同属一个包，编译时合并为一个整体——`const.go`、`auth.go` 只是物理上分文件，和 `router.go` 逻辑上是同一个包。常量大写开头（`APIVersion`）是为了让需要时其他包也能读它；如果确定只在本包用，小写开头即可。

### 3.3 优先用标准库现成的常量

HTTP 状态码不要自己定义数字，`net/http` 全都有：

```go
c.JSON(http.StatusOK, gin.H{...})   // 而不是 c.JSON(200, ...)
```

## 四、踩坑记录

### 4.1 分组改造后的"双前缀"问题（已修复）

最初 `business.go` 里写过：

```go
api := r.Group("/api") // 参数 base 已经是 /api/v1 了！
```

由于传入的 `base` 前缀已经是 `/api/v1`，再套一层 `/api` 后实际路径变成了 **`/api/v1/api/orders`**——多了一段。这是把路由挂到分组时最容易犯的错：**子分组只声明"增量"部分**。

修复后的写法（即当前代码）：不再套子分组，路由直接挂在传入的 `base` 上：

```go
func registerBusinessRoutes(r *gin.RouterGroup) {
	r.GET("/orders", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"message": "订单列表"})
	})
	r.POST("/orders", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"message": "创建订单"})
	})
}
```

### 4.2 常量名拼写（已修复）

最初 `main.go` 中常量写成了 `DefaultProt`，少了一个字母，应为 `DefaultPort`。常量一旦被多处引用，改名要靠 IDE 的重构功能（VS Code 中 F2）一次改完，避免手改漏网。

### 4.3 变量命名惯例（已修复）

- gin 引擎的习惯命名是 `r`，最初的 `routersInit` 已简化，不需要刻意起"描述型"名字。
- 包内局部变量不要和包名撞名（`router` 包里再叫一个 `router` 变量虽然合法，但容易混淆）。
